## 📌 โจทย์ (Problem Statement)

### สถานการณ์ทางธุรกิจ (Business Scenario)
บริษัท TicketChain เป็นแพลตฟอร์มจำหน่ายตั๋วคอนเสิร์ตและงานแสดงสด ปัจจุบันพบปัญหาตั๋วปลอมและตั๋วซ้ำ ที่นั่งเดียวกันถูกขายให้หลายคน และกลุ่มนายหน้ากว้านซื้อตั๋วไปขายต่อในราคาสูงเกินจริง ผู้จัดงานไม่มีรายได้จากการขายต่อ ผู้ชมไม่มั่นใจว่าตั๋วที่ซื้อจากบุคคลอื่นเป็นของจริง และเมื่องานถูกยกเลิก การคืนเงินใช้เวลานานและเกิดข้อพิพาท

บริษัทจึงต้องการพัฒนาระบบที่ใช้ Smart Contract บน Ethereum ออกตั๋วเป็น NFT ผูกกับที่นั่งเฉพาะบุคคล ควบคุมการขายต่อให้อยู่ในราคาที่เหมาะสม และรับประกันเงินคืนเมื่องานถูกยกเลิก

### ฟังก์ชันที่ต้องการ (Functional Requirements)
1. **ลงทะเบียนผู้จัดงาน (Register Organizer)** ผู้ดูแลระบบกำหนดสิทธิ์ผู้จัดงานที่สร้างคอนเสิร์ตได้
2. **สร้างคอนเสิร์ตและโซนที่นั่ง (Create Concert & Zones)** ผู้จัดงานระบุชื่องาน สถานที่ เวลาแสดง เพดานราคาขายต่อ และกำหนดโซนที่นั่ง ราคา และจำนวนที่นั่งของแต่ละโซน (โซนละอย่างน้อย 10 ที่นั่ง)
3. **เลือกที่นั่งและซื้อตั๋ว (Buy Ticket / Mint NFT)** ผู้ชมเลือกคอนเสิร์ต เลือกโซนจากผังเวที เลือกที่นั่ง และชำระ ETH ตามราคาโซน ได้รับตั๋วเป็น NFT
4. **ติดตามที่นั่งว่าง (Seat Availability)** แสดงผังเวที สีตามระดับราคา และจำนวนที่นั่งว่างของแต่ละโซนแบบเรียลไทม์
5. **ขายต่อในราคาจำกัด (Controlled Resale)** ผู้ถือตั๋วลงขายต่อผ่านตลาดของระบบ ราคาต้องไม่เกินเพดานที่ผู้จัดงานกำหนด และผู้จัดงานได้ค่าธรรมเนียมจากการขายต่อ
6. **ตรวจตั๋วและเข้างาน (Gate Check-in)** เจ้าหน้าที่ประตูตรวจตั๋วด้วย QR Code และบันทึกการใช้ตั๋ว ตั๋วใช้เข้างานได้ครั้งเดียว
7. **ยกเลิกงานและขอเงินคืน (Cancel & Refund)** เมื่อผู้จัดงานยกเลิกคอนเสิร์ต ผู้ถือตั๋วขอเงินคืนตามราคาตั๋วได้
8. **แสดงความโปร่งใส (Transparency)** แสดงประวัติการซื้อ ขายต่อ เข้างาน และการเงิน พร้อม Transaction Hash

### กฎทางธุรกิจสำคัญ
- **1 ที่นั่งขายได้ครั้งเดียว** และตั๋วที่ใช้เข้างานแล้วใช้ซ้ำไม่ได้
- **ตั๋วโอนตรงระหว่างกระเป๋าไม่ได้** ต้องขายต่อผ่านตลาดของสัญญาเท่านั้น และราคาขายต่อต้องไม่เกินเพดาน
- **เงินของผู้ซื้อปลอดภัย** ผู้จัดงานรับรายได้ได้หลังเริ่มการแสดงเท่านั้น

### ผลลัพธ์ที่คาดหวัง
ระบบจำหน่ายตั๋วที่ป้องกันตั๋วปลอมและที่นั่งซ้ำ ลดการกักตุนโก่งราคา สร้างรายได้ให้ผู้จัดงานจากการขายต่อ และเพิ่มความเชื่อมั่นของผู้ชมด้วยการรับประกันเงินคืน

## ✅ ฟังก์ชันตามโจทย์

| # | ความต้องการ | ฟังก์ชันใน Smart Contract | ส่วนในหน้าเว็บ |
|---|---|---|---|
| 1 | ลงทะเบียนผู้จัดงาน | `setOrganizer(account, enabled)` | แท็บ "ผู้ดูแล" |
| 2 | สร้างคอนเสิร์ตและโซน | `createConcert(...)`, `addZones(...)` | แท็บ "ผู้จัดงาน" (สร้าง 30 โซนตามผังมาตรฐาน โซนละ ≥ 10 ที่นั่ง) |
| 3 | ซื้อตั๋ว (Mint NFT) | `buyTickets(zoneId, seats[])` | ผังที่นั่ง → คลิกโซน → เลือกที่นั่ง → ซื้อ |
| 4 | ติดตามที่นั่งว่าง | `getZones`, `getZoneSeats` | สีโซนตามราคา, ตัวเลขว่าง/ทั้งหมด, ตารางที่นั่ง |
| 5 | ขายต่อในราคาจำกัด | `listForResale`, `cancelListing`, `buyResale` | แท็บ "ตั๋วของฉัน" + ตลาดขายต่อในหน้าคอนเสิร์ต |
| 6 | ตรวจตั๋ว/เข้างาน | `verifyTicket`, `checkIn`, `setGateStaff` | แท็บ "ประตู / ตรวจตั๋ว" + QR Code |
| 7 | ยกเลิกงานและคืนเงิน | `cancelConcert`, `refundTicket`, `withdraw` | แท็บ "ผู้จัดงาน" / "ตั๋วของฉัน" |
| 8 | ความโปร่งใส | Events ทุกรายการ, `releaseRevenue` | "ประวัติธุรกรรมและ Transaction Hash" ในหน้าคอนเสิร์ต |

### การเลือกโซนและที่นั่งในหน้าเว็บ
1. หน้าแรกแสดงเฉพาะรายชื่อคอนเสิร์ต **ผังที่นั่งจะปรากฏเมื่อคลิกที่ชื่อคอนเสิร์ต**
2. โซนในผังแสดงสีตามระดับราคา (2,000–7,000 บาท ตามผังมาตรฐาน) และจำนวนที่นั่งว่าง
3. คลิกโซนเพื่อดูตารางที่นั่ง (โซนละอย่างน้อย 10 ที่นั่ง) เลือกที่นั่งแล้วกดซื้อ
4. ราคาในระบบกำหนดเป็น ETH โดยผู้จัดงานตั้งอัตรา "ETH ต่อ 1,000 บาท" (ค่าเริ่มต้น 0.001 → โซน A2 7,000 บาท = 0.007 ETH)

## 🔒 กฎทางธุรกิจและการป้องกัน

| กฎ | วิธีที่สัญญาบังคับ |
|---|---|
| ห้ามขายที่นั่งซ้ำ | เก็บ `seatToken[zone][seat]` ที่นั่งที่ถูกขายแล้วซื้อซ้ำไม่ได้ |
| ตั๋วใช้ได้ครั้งเดียว | `checkIn` เปลี่ยน `used = true` และตั๋วที่ใช้แล้วขายต่อ/เข้างานซ้ำไม่ได้ |
| ห้ามโอนตั๋วตรง ๆ | override `_update` ของ ERC-721 อนุญาตเฉพาะ mint, burn และการโอนที่สัญญาทำเองในตลาดขายต่อ (`transferFrom`/`safeTransferFrom` ถูกปฏิเสธ) |
| จำกัดราคาขายต่อ | `listForResale` ตรวจ `price <= ราคาซื้อ × resaleCapBps / 10000` (100%–200%) |
| กันกักตุน | ซื้อรอบแรกได้ไม่เกิน `maxPerWallet` ใบต่อกระเป๋า (1–10) |
| ผู้จัดงานได้ส่วนแบ่งการขายต่อ | ราคาขายต่อ 95% ให้ผู้ขาย และ 5% ให้ผู้จัดงาน |
| เงินผู้ซื้อปลอดภัย | รายได้รอบแรกถูกกันไว้ในสัญญา ผู้จัดงานรับได้หลังเริ่มการแสดงเท่านั้น (`releaseRevenue`) |
| ยกเลิกงานแล้วคืนเงิน | `cancelConcert` ก่อนเริ่มแสดง → ผู้ถือตั๋วเรียก `refundTicket` ได้เงินตามราคาตั๋ว (ตั๋วถูกเผา) |
| สิทธิ์ตามบทบาท | เฉพาะ Admin ลงทะเบียนผู้จัดงาน, เฉพาะผู้จัดงานของงานนั้นจัดการงาน/แต่งตั้งเจ้าหน้าที่ประตู, เฉพาะเจ้าหน้าที่ประตูของงานนั้น Check-in |
| ความปลอดภัยการโอนเงิน | Pull payment (`withdraw`), Checks-Effects-Interactions, `nonReentrant` และสัญญาไม่รับ ETH ที่โอนตรง ๆ |

**NFT metadata:** `tokenURI` สร้างบนเชน (Base64 JSON) ระบุชื่อคอนเสิร์ต โซน และเลขที่นั่ง

### ขั้นตอนที่ 1 — เตรียม MetaMask และบัญชีทดสอบ
1. ติดตั้ง [MetaMask](https://metamask.io) แล้วเลือกเครือข่าย **Ethereum Hoodi** (chainId 560048) — เมื่อกดเชื่อมต่อในหน้าเว็บ ระบบจะขอสลับ/เพิ่มเครือข่ายให้อัตโนมัติ
2. เตรียมบัญชีทดสอบ **อย่างน้อย 4 บัญชี**

| บทบาท | หน้าที่ |
|---|---|
| ผู้ดูแล (Admin) | บัญชีที่ **Deploy สัญญา** ลงทะเบียนผู้จัดงาน |
| ผู้จัดงาน (Organizer) | สร้างคอนเสิร์ต แต่งตั้งเจ้าหน้าที่ประตู ยกเลิกงาน รับรายได้ |
| ผู้ชม A, B (Fan) | ซื้อตั๋ว ขายต่อ |
| เจ้าหน้าที่ประตู (Gate Staff) | Check-in (ใช้บัญชีผู้จัดงานหรือบัญชีผู้ชมที่ไม่ได้ใช้งานก็ได้) |

3. ขอ ETH ทดสอบจาก Faucet ของ Hoodi แล้วโอนให้ทุกบัญชี (ผู้ชมควรมีอย่างน้อย 0.05 ETH)

### ขั้นตอนที่ 2 — คอมไพล์และ Deploy ใน Remix IDE
1. เปิด [Remix IDE](https://remix.ethereum.org) สร้างไฟล์ `ConcertTicketNFT.sol` แล้ววางโค้ด (ต้องต่ออินเทอร์เน็ตเพื่อให้ Remix ดาวน์โหลด OpenZeppelin ตามบรรทัด `import`)
2. แท็บ **Solidity Compiler** เลือกเวอร์ชัน **0.8.20 ขึ้นไป** แล้ว Compile
3. แท็บ **Deploy & Run** เลือก Environment เป็น **Browser Extension → MetaMask** บัญชี **Admin** เครือข่าย Hoodi ตั้ง Value = `0` แล้วกด **Deploy** (ไม่มี parameter ใน constructor)
4. คัดลอก **Contract Address** จากแท็บ Deployed Contracts

**ทดสอบยกเลิกและคืนเงิน:** สร้างคอนเสิร์ตที่สอง ให้ผู้ชมซื้อตั๋ว แล้วผู้จัดงานกด "ยกเลิกคอนเสิร์ต" (ก่อนเวลาแสดง) ผู้ชมไปที่ "ตั๋วของฉัน" กด "ขอเงินคืน" แล้วกด "ถอนเงิน"

**ทดสอบกฎป้องกัน:** ลองซื้อเกินจำนวนต่อกระเป๋า และลองโอนตั๋วตรงจาก Remix (`transferFrom`) ซึ่งจะถูกปฏิเสธด้วยข้อความ `Direct transfer disabled: use resale market`

### ขั้นตอนที่ 5 — Deploy หน้าเว็บบน GitHub Pages
1. สร้าง Repository ใหม่ อัปโหลด `index.html`, `ConcertTicketNFT.sol` และ `README.md`
2. **Settings → Pages** → Source: **Deploy from a branch** → Branch `main` / `/ (root)` → Save
3. รอ 1–2 นาที ลิงก์จะเป็น `https://<username>.github.io/<repo-name>/`

## ⚠️ ข้อจำกัดและแนวทางพัฒนาต่อ

- ผังเวทีเป็นผังมาตรฐาน 30 โซนที่ฝังในหน้าเว็บ (ตำแหน่งโซนกำหนดฝั่งหน้าเว็บ ส่วนราคาและจำนวนที่นั่งอยู่บนเชน) ควรให้ผู้จัดงานปรับผังได้เอง
- ตั๋วโอนตรงไม่ได้เลย (รวมถึงการให้เป็นของขวัญ) อาจเพิ่มฟังก์ชัน "โอนให้เพื่อนในราคาเท่าทุน" ที่ผู้จัดงานอนุมัติ
- กฎจำกัดจำนวนต่อกระเป๋าหลบได้ด้วยการใช้หลายกระเป๋า ควรเพิ่มการยืนยันตัวตน (KYC) หรือ Allowlist
- QR Code เป็นลิงก์ตรวจตั๋ว ไม่ได้ลายเซ็นของผู้ถือ ผู้ที่เห็น QR สามารถนำไปแสดงแทนได้ ควรพัฒนาเป็น QR แบบหมุนเวียนที่ผู้ถือเซ็นด้วยกระเป๋า
- งานที่ถูกยกเลิกคืนเงินตามราคาตั๋วรอบแรก (ผู้ซื้อตั๋วต่อได้คืนตามราคาตั๋วเดิม ไม่ใช่ราคาที่จ่ายจริง)
- รองรับเฉพาะ ETH ยังไม่รองรับ Stablecoin และสัญญายังไม่ผ่านการตรวจสอบความปลอดภัย (audit) ใช้เพื่อการศึกษาบน Testnet เท่านั้น
